# Development roadmap

[Documentation index](../README.md)

> Target architecture derived from Project PT specification v3.0, November 2026. These are planned capabilities unless explicitly stated otherwise.

Implement phases with working deliverables. The phase numbers preserve the supplied specification.

| Phase | Focus | Deliverable | Exit criterion |
| --- | --- | --- | --- |
| 0 | Foundation | Repository, local inference, microphone test, database, logging, configuration | Local model and basic application run reliably |
| 1 | Voice assistant | Wake word, transcription, basic tools, TTS, desktop status | “Hey PT, open VS Code” works end-to-end |
| 2 | Academic knowledge | Document import, parsing, indexing, hybrid search, cited answers | Correct lecture passages with page references |
| 3 | Academic workflows | Study guides, questions, grading, performance records, PDF generation | Complete revision workflow produces a verified PDF |
| 4 | Memory and productivity | Reviewable long-term memory, reminders, schedules, calendar tools | Tasks persist and operate correctly after restart |
| 5 | Desktop experience | Orb, chat dashboard, streaming responses, interruptible speech, screen analysis | Stable daily-use desktop assistant |
| 6 | Trading analytics | Read-only MT5 reports, OrbCatcher data, backtests, risk analysis, Monte Carlo | Validated analytics with no execution access |
| 7 | Multi-device platform | Authenticated remote clients, Pi telemetry, backups, deployments | Secure operation across approved devices |

See [evaluation targets](evaluation.md), [engineering goals](engineering-goals.md), and the [flagship academic workflow](../workflows/academic-study-guide.md).
